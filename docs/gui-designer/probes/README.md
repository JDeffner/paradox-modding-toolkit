# Cross-game calibration probes (Vic3 / EU5 / any Jomini title)

The CK3 campaign (batch-01..04 + the 2026-08-02 probe) measured the layout
rules the engine implements; those defaults are CK3-tuned. These probes carry
the same experiments to OTHER games, packaged so they need nothing from the
target game: no vanilla templates, no localization keys, and a mod-local
white texture (`gfx/px_probe/white.dds`, written by the repo's own DDS
encoder — 8x8 opaque white, uncompressed BGRA8).

## The five windows

| Window | Covers | CK3 provenance |
|---|---|---|
| `px_probe_a` | ruler/scale, parentanchor matrix, widgetanchor default, position after anchoring, hbox/vbox stretch + space-around, spacing, margin, nesting | batch-01 (same case geometry, so the CK3 numbers are the predictions) |
| `px_probe_b` | explicit size on a box, box-in-box hug, position on a box child (L23), margin_top, expanding/growing/deficit policies, expand spacer, minimumsize floor, policy-less deficit (unmeasured everywhere — new) | batch-02/03, B4-T7/T8, probe 2026-08-02 |
| `px_probe_c` | flowcontainer hug/no-wrap/sized (L13e), container hug/sized/empty (L25), margin_widget sized+sizeless, scrollarea clip, sizeless widget, percent size, icon scale | batch-02/03/04, probe 2026-08-02 |
| `px_probe_d` | text metrics at EXPLICIT fontsize: M/i/space advances, linear scaling, max_width, multiline, align | batch-01/03/04 (CK3 numbers are Gitan-Regular; other games have other fonts — deviations expected and wanted) |
| `px_probe_e` | the game's own `text_single` template and the bare-textbox default size. Isolated window: if the template does not exist, only this window fails | — |

`engine-predictions.txt` is generated by running every window through
`computeGuiLayout` (the CK3-tuned engine): each node's canvas-relative rect.
That file is the prediction column — anything the screenshot disagrees with
is the calibration data. Regenerate after editing a probe:
the generator script lives in the session scratchpad as
`gen-probe-assets.ts` (esbuild-bundle it, run with node; it also rewrites
`gfx/px_probe/white.dds`).

## Method per game

1. Package `gui/` + `gfx/` as a mod for the target game (Vic3:
   `.metadata/metadata.json` at the mod root; EU5: same, with content under
   `in_game/`).
2. Launch with `-debug_mode`, enter a game, open the console.
3. `gui.createwidget gui/px_probe_a.gui px_probe_a` … one window at a time,
   `gui.clearwidgets px_probe_a` before the next.
4. PNG screenshot per window (Win+PrtScr — never Steam F12 JPG), 100% UI
   scaling, note the resolution.
5. Collect `Documents/Paradox Interactive/<game>/logs/error.log` — the engine
   corroborates rules in text ("Widget cannot have a position in a layout",
   "You should not set a size on a container").
6. Analyze with `../analyze.ps1` (flat unique colors -> exact bounding
   boxes), write the game's expectations file, then move the deltas into the
   layout engine behind the GameProfile seam.

Packages: `../eu5/package/` (self-contained, for an external runner),
`../vic3/probe.md` (run checklist; the mod is installed straight into the
local Vic3 mods folder).
