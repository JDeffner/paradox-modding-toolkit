# Paradox Modding Toolkit 0.4.0 (beta)

Everything the 0.3.5 and 0.3.6 pre-releases carried reaches everyone now:
Steam Workshop publishing, the mod projects layout and the Examples Wiki, on
the normal channel, with no "pre-release version" box to tick. What 0.4.0 adds
on top is six visual creators for Crusader Kings III. Most of a trait, a
legacy track, a culture, a tradition, a dynasty or a coat of arms can now be
made without typing script.

### The content creators

Each one opens from the Project panel's Create group, as a form over the keys
the game itself documents, with the game's own art and text beside it. Every
value the toolkit indexes is a picker instead of a blank box, and every empty
input shows the value the game writes most as its placeholder. Opening
something you already have loads it and writes back only the lines you
changed, so your comments and formatting survive. None of them validates your
script: ck3-tiger stays the validator.

- **Trait Creator.** The 60 keys `_traits.info` documents, each with the
  game's own explanation, next to a live preview of the tooltip the game
  prints: framed icon at 52 px, skill and modifier lines run through the
  game's format rules, opposites, flags. A new trait saves with only a name
  typed.
- **Dynasty Legacy Creator.** A track and its five perks designed together
  (five, because that is the number every vanilla track has), drawn as the
  game's legacy row with the 4216x368 illustration behind it. `is_shown`,
  `can_be_picked` and a perk's `effect` are rows over the DLC features, game
  rules and scripted triggers the game files use, with raw script kept as the
  fallback that round trips unchanged.
- **Culture Creator.** The five pillars as one picker each, traditions as
  searchable chips carrying the game's description, name lists, art sets,
  ethnicities, a color, and parents plus a creation date for a hybrid or
  divergent culture. The preview is the culture window's own header, tinting
  the pillar icons the way `icon_flat_standard` tints them. It round trips two
  vanilla cultures byte for byte.
- **Tradition Creator.** `common/culture/traditions`, with the icon composed
  from the game's own layer folders, the cost printed as the game's
  `<CURRENCY>_COST` line, and parameters as switches whose tooltip reads in
  plain words: "The Rough Terrain Expert Commander Trait is more common",
  rather than the `[GetTrait(…).GetName(…)]` call the file holds.
- **Dynasty Tree.** Any dynasty of the game or your mod as a family tree:
  couples under a marriage bar, children centered under their own. Cards edit
  through pickers, Add child and Add spouse work on vanilla characters too,
  dates are typed in the mod's calendar, and a character's DNA carries the
  portrait with Open, Copy and Paste. Every write is one undo.
- **Coat of Arms Designer.** The CK3 answer to the Flag Builder: Background,
  Layout and Emblems tabs over the designer's own data files, multi-select
  with align, distribute, mirror and nudge, a grid from 16x16 to 64, and a
  library of your designs stored outside any mod. Dynasty, house and title
  frames come as sprite sheets of six tiers, each named after the heritages
  whose cultures wear it, and the arms are sized the way
  `gui/shared/coat_of_arms.gui` sizes them: across the 31 vanilla frames that
  fills 99.9% of the frame's window and keeps the arms square. Textures decode
  on worker threads, so opening the designer on a large mod stalls the
  extension host for 9 ms instead of 1.7 s. The Flag Builder stays as it was
  for Victoria 3 and EU5.

### A wiki that knows what else is out there

**Modding Tools** is a new page per game, listing the tools other modders
built for the game you are modding, curated from that game's own wiki list:
validators, translators, map and history editors, audio and 3D tools. Tools
the toolkit already does the job of are left out, so the page never sends you
to install something you have.

A game switch at the top of the wiki sidebar reads another game's pages
without changing the workspace. Home, Credits and a Steam Error Codes table
are pages now, and the front page is a set of cards over the Examples Wiki,
format docs, image guidelines, diagnostics and the mod report.

The Examples Wiki itself searches every trigger, effect, event target,
modifier, datafunction, keyword and scope word the game reported about itself,
ranked by real usage count, and every hover in the editor links to the
matching article.

### Steam Workshop publishing, official

The panel uploads through your running Steam client: no launcher, no web form,
no password typed anywhere. New items are created private, and the id lands
where the game's tooling expects it. This round rebuilt the panel around what
actually leaves your machine:

- **The changenote says where it comes from.** Changelog, Last commit and
  Write are one segmented choice, and the picked one is exactly what uploads.
  The changelog entry is shown as rendered BBCode with its file named, the
  commit as the plain text it is sent as.
- **The listing is files, and the text is edited in its file.** The panel
  shows rendered BBCode previews with an Edit file button; each preview starts
  at a fixed height, scrolls on both axes and has a drag grip, so a long
  description no longer pushes the page away. Every description row carries
  the same three buttons. A `.bbcode` file also opens as Markdown in place,
  and a question-mark button in its title bar opens the wiki's BBCode page.
- **`.pxignore` decides what an upload leaves out.** gitignore syntax at the
  mod root, with its own language mode, created with sensible defaults on the
  first upload. `.pxignore` and the `.px-toolkit/` config folder never upload,
  which is also where the generated tiger conf now lives, so your validator
  settings stay local.
- **Requirements has its own switch.** Required DLC comes from the game's own
  `game/dlc/*/*.dlc` files as a grid of their icons; required items wrap as
  chips. Sending a corrected title no longer rewrites what the item declares.
- **Previews and pre-upload checks.** A `previews/` folder holds the gallery,
  videos lead it and open on click, and the order is drag and drop. Before
  anything reaches Steam the Publish card lists what would go wrong: an
  overlong title, a description over 8000 bytes, a preview of 1 MB or more.
- **A failure says what to do about it.** The advice table is keyed on the
  EResult name now and covers 32 codes, worded from the per-call result lists
  Valve documents rather than the generic enum text. On an upload
  `LimitExceeded` is a preview image over 1 MB, not a long description.

### The display calendar lives in the mod

A total-conversion mod declares its era system in
`<mod>/.px-toolkit/calendar.json` (`Paradox: Declare Calendar` writes an
editable example), committed with the mod and read wherever the mod is opened.
One calendar per mod in a multi-mod window, and bare LSP clients need no
settings plumbing because the server reads the file itself. Date hints, hover,
Insert Date and Generate Calendar Localization all follow it.

### Snippets measured from the game

Typing at the top of a script file offers a skeleton of that folder's
definition kind: 119 kinds for Crusader Kings III, 93 for Victoria 3, each the
shape the game's own files write most (keys present in at least half the
vanilla definitions, in their usual order, with the most written value
pre-filled as a tabstop). An empty line inside a definition offers its common
child blocks. `Insert Snippet…` (Ctrl+Alt+I) lists those next to the engine's
own block examples.

Those block examples got fuller too. An example whose `#` comments only mark
fields optional now produces two templates instead of none, the required
fields and every field, and a multi-line example is followed to its closing
brace instead of being cut after line one. Over the shipped dumps that is 679
CK3 templates before and 718 after; Vic3 stays at 265.

### Also in this release

`Paradox: Move Mod` converts a mod between the game folder layout and the mod
projects layout in either direction, carrying the Workshop listing with it.
The event graph leaves out events nothing fires and that fire nothing, before
it reads their cards. A Credits panel lists every upstream project the toolkit
builds on. Seven modal dialogs became bottom-right notifications with the same
buttons. `@px-lsp/server` 0.3.1 and `@px-lsp/protocol` 0.2.1 add the wire
requests the creators are built on: `paradox/definitionForm`,
`paradox/definitionEdit`, `paradox/dynastyTree`, `paradox/modifierFormats`,
`paradox/locText` and `paradox/snippets`.
